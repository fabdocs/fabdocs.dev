Governance in Fabric is layered: tenant settings, workspace roles, item
permissions, and — newest and most powerful — **OneLake security** for
row/column/table-level control that every engine honors.

## The layers, top to bottom

| Layer | Controls | Set by |
| --- | --- | --- |
| Tenant settings | Who can use SPNs, create capacities, share externally | Fabric admin |
| Capacity | Which workspaces run where; surge protection | Capacity admin |
| Workspace roles | Admin / Member / Contributor / Viewer | Workspace admin |
| Item permissions | Per-report / per-model sharing | Item owner |
| **OneLake security** | Row / column / table access on lakehouse data | Data owner |

<Callout type="info">
Design top-down but review bottom-up: an auditor asks "who can read this table",
and the answer is the *intersection* of every layer. Document the whole chain
for your regulated datasets.
</Callout>
