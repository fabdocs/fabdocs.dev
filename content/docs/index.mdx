Official Microsoft documentation tells you **what** every Fabric feature is.
`fabdocs.dev` is about **how** to run it in production — how to build, deploy,
govern, and scale lakehouses, notebooks, and pipelines without torching your
capacity budget.

## Who this is for

- **Data engineers** taming lakehouses, Spark jobs, and Delta table sprawl.
- **Enterprise architects** designing OneLake topology, security, and CI/CD.
- **Analytics leads** who own a capacity and need CU burn to be predictable.

## Conventions used in this manual

| Callout | Meaning |
| --- | --- |
| **CU impact** | How the pattern changes Capacity Unit consumption. |
| **Runtime** | Minimum Fabric Runtime / Spark version required. |
| **Reversible?** | Whether the change can be rolled back without a reload. |

Every page states its CU impact up front. If a technique saves money, that is
the headline — not a footnote.
